# 付款前卡台余额检查

商品订单在创建或复用付款信息前，按上游连接汇总订单中的采购成本上限（成本快照 × 数量）。父订单只计子订单明细一次，避免重复计算。该上限与采购提交使用的 `MaxAmount` 相同，不能用商城售价、微信手续费或 USDT 数量代替。

适用入口：游客及会员的创建订单并付款、独立付款、继续付款和最新付款信息读取，统一覆盖 BEP20、Plasma、TRON USDT、XorPay 微信，以及商品订单的钱包全额/混合支付。独立钱包充值没有对应商品采购成本，仍按原充值流程处理；充值后的商品消费经过同一检查。

## 付款拦截

- 余额不足返回 `card_platform_insufficient_balance`，弹窗显示“卡台余额不足”，明确要求联系客服补充卡台余额。
- 查询超时、查询失败、余额格式异常、币种不符、缺少供货映射或有效成本时，返回 `card_platform_balance_unavailable`，暂停付款并提示稍后重试或联系客服。
- 拦截发生在钱包扣款、支付单创建和第三方网关请求之前。已创建的未付款订单保留，可在余额恢复后继续付款；同一结算内容在页面内重试复用该订单。
- 付款页恢复缓存必须经过服务端校验；显示中的付款信息每 30 秒复核一次，重新打开外部收银台前再检查。检查失败会隐藏付款信息。
- 客服微信固定为 `Cqz0924ttxk`。经典与 Vault 模板共用同一个弹窗，支持键盘关闭、焦点返回与复制微信号。

## 邮件状态

余额不足触发的提醒使用通知中心已经配置的邮件渠道及收件人。作为付款拦截的专用提醒，它不依赖一般异常告警场景开关；邮件渠道未启用或无收件人时显示未发送。通知日志仍归类为异常提醒，业务类型以 `supplier_balance_` 开头。

提醒通过持久化队列发送，不阻塞付款响应。弹窗读取实际状态：

| 状态 | 客户文案 |
| --- | --- |
| pending | 充值提醒已提交，邮件发送结果待确认 |
| sent | 已发送邮件通知客服充值 |
| partial | 部分提醒邮件已发送，请联系客服 |
| failed | 邮件提醒未发送成功，请直接联系客服 |
| not_sent | 暂未发送邮件提醒，请直接联系客服 |

发送中每 3 秒查询一次状态，最多约一分钟，关闭弹窗即停止查询。状态接口验证订单归属和所对应的供货连接；只读取状态，不触发付款、采购、查余额或发信。

同一上游连接合并重复提醒，成功或部分成功后冷却 30 分钟，失败后冷却 1 分钟。每个收件人的发送结果记入通知日志，重复队列投递跳过已成功收件人。只有 SMTP 接受邮件后才显示成功，不把入队成功当成发送成功；SMTP 接受也不等于邮件已进入收件箱。

## 已有付款与边界

检查是付款前的余额快照，上游没有提供余额冻结接口。客户等待付款时，上游其他消费、已生成二维码或用户已复制的转账地址仍可能使余额变化；本站不能撤回用户已保存的付款信息。

已到账的有效回调继续验签、核对金额并持久化，不能因余额检查失败丢弃到账事实。若随后采购遇到余额不足，订单保留已付款状态并显示联系客服的交付异常；不伪造退款，不自动重试结果不明的采购。
