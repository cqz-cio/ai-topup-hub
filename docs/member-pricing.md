# 会员商品优惠价

## 后台设置

1. 在「会员等级」中建立等级，保留默认等级、充值/消费升级门槛和排序。新注册用户仍分配默认等级；门槛都为 0 时不自动升级到该等级，管理员可以手动分配。
2. 在会员等级列表点击该等级的「设置商品价」，集中填写各商品的「本商品默认价」和各规格优惠金额，例如商品 A 为 70 元、商品 B 为 130 元。每个等级独立设置，不再填写统一折扣率。
3. 商品列表原有的「等级价格」入口仍可使用，便于对同一商品比较和设置不同等级的价格；两个入口使用同一份数据。
4. 在「用户管理」打开用户详情并分配等级。用户已有个人专属价时，个人价优先。

本次更新不会自动创建等级、调整商品零售价或改变用户等级。未填写的价格不会自动根据历史折扣换算，需填写实际希望使用的商品金额。

## 显示与结算规则

- 个人专属价优先；未设置个人价时，按「规格会员价 → 本商品默认会员价 → 商城当前价」取价。
- 不再使用会员等级的历史百分比折扣，也不在固定金额上继续打折。会员固定价只在低于商城当前价时生效，更低的活动价和数量优惠继续保留。普通促销与优惠券的其他既有规则不变。
- 留空并保存会清除该项；清除规格价后可继承商品默认会员价，两者都留空则恢复商城当前价。
- 按等级保存只替换该等级，按商品保存只替换该商品，均使用事务。搜索隐藏的商品、未显示的下架商品及停用规格已有价格会保留。
- 会员充值、消费累计及自动升级照常运行，升级后使用新等级中明确设置的商品价格。
- 首页采用默认展示规格的一件价格，详情按当前规格和数量显示。购物车、立即购买和下单预览使用相同规则，最终金额由后端重新核价并写入订单。历史订单金额不回算。
- 管理员调整用户等级后无需重新登录。重新加载商品或结算页面、回到窗口，以及可见页面每分钟刷新时会读取最新等级。退出或换账号后重新取价。
- 未指定、已删除或停用的等级按商城价及公开优惠计算。游客不能提交等级 ID 获取会员价；公开商品接口只返回当前用户所属等级的固定价。
- 个性化商品响应保持 `Cache-Control: private, no-store` 和 `Vary: Authorization`，防止不同身份共用缓存价格。

## 接口兼容

复用现有会员等级、用户等级和等级商品价格表，无需新增数据库字段。`discount_rate` 仅为兼容保留：创建及更新等级固定写入 100，公开等级和商品接口返回 100，定价逻辑忽略历史值。

价格接口沿用现有读写权限。`GET /admin/member-level-prices` 必须指定 `product_id` 或 `member_level_id` 其中一个。`POST /admin/member-level-prices/batch` 带 `member_level_id` 时完整替换该等级价格；带 `product_id` 时完整替换该商品价格；两者不能同时指定。旧的不带范围参数的批量更新继续有效。

回归覆盖固定价、未配置回退、历史折扣失效、个人价优先、促销和数量优惠、等级隔离、清空恢复、事务回滚及等级自动升级。资金相关测试仅使用模拟数据，不进行真实收款或采购。
