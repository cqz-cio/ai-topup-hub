# 已付款订单数据库死锁修复

2026-10-16，新加坡后端发布 `20261016-190912`，源码为已推送的 `main` 提交 `b9459c9e493588ce943289f4349a3b2a27762512`。运行程序 SHA256 为 `e224f3d6f7f6dc540a101230b39975be657493d99196b7f1458ab7c628ab6c0b`，Go 1.26.5、`release,fullstack`、`vcs.modified=false`。文档提交不代表程序再次构建。

## 原因与修改范围

生产 SQLite 连接池的 `max_open_conns` 与 `max_idle_conns` 均为 1。原 `HandleOrderPaid` 先开启返佣事务，再通过独立设置仓库读取返佣配置：事务占着唯一连接，配置查询又等待连接，形成自我等待。返佣关闭或比例为零也会触发，可能进一步阻塞商品、配置及后台查询。

修复在开启事务前取得返佣配置，将配置快照传入事务内的处理函数；佣金写入、幂等检查和处理标记仍在原事务中。配置读取失败时不写处理标记，保留后续恢复机会。

对比先前正式后端 `41af36617cd9f267520bd934299394ce74f416e6`，运行代码仅修改 `internal/modules/affiliate/application/commission.go`，另增加两个测试文件的覆盖。没有调整数据库连接数、付款金额、渠道配置或采购算法。
