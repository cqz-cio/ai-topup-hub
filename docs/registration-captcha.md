# 注册图形验证码

注册页沿用现有图形验证码和邮箱验证流程：填写邮箱、密码和图形验证码后，点击“发送验证码”；后端校验图形验证码，通过后才发送邮件。收到邮箱验证码并同意协议后创建账号。

- “图形验证码”和“邮箱验证码”分别标注，沿用原注册布局；简体中文、繁体中文和英文同步。
- 图形验证码支持“换一张”。输入错误、验证失败或需要重新发送时可刷新图片，已填写的邮箱和密码保留。
- 当前设置为 5 位字母数字、有效期 300 秒。每次校验都会消耗该图片验证码，不能重复使用。
- 注册仍要求邮箱验证。直接调用注册接口也必须提交有效的邮箱验证码；图形验证码保护的是发送邮件步骤。

## 配置维护

后台“系统设置 → 验证码设置”：提供方选“图片验证码”，开启“注册发送验证码”。公开配置仅下发开关；答案不发送到前端。

最小配置补丁见 [registration-captcha.json](catalog/registration-captcha.json)，通过既有 `PUT /api/v1/admin/settings/captcha` 接口应用。仅修改 `provider=image` 和 `scenes.register_send_code=true`，保留图片参数、其他场景与服务密钥。必须保持注册和邮箱验证开启；关闭邮箱验证会绕过发送邮件步骤，现有版本的图形验证也不会触发。

## 验证与发布

在日常 `8080/5173/5174` 入口先备份本机数据、应用配置并检查页面和实际验证码接口。检查换图、空验证码、错误验证码、失败后刷新及邮箱密码保留，核对 1920、390、320px 显示。验证码服务回归验证有效挑战和失败挑战均只能使用一次。

发布仅替换上海商城静态资源并通过新加坡既有管理接口更新上述两项配置；保留后台静态资源、新加坡程序、订单与支付采购配置。先备份两地当前资源、数据库和私有配置，不上传本机数据库。有效邮件发送与完整注册流程使用本地模拟邮件服务或单元测试，不向真实收件人发送验收邮件。
