# BSC 到账扫描接口恢复

2026-10-16 原默认 PublicNode 接口返回 HTTP 403。使用明确的应用 User-Agent 后基础查询可用，但积压区间的 `eth_getLogs` 仍明确要求个人归档访问令牌。客户付款数量少不意味着扫描请求少：监听器每 10 秒运行；数据库故障期间积压的区块也必须完整补扫。接口何时改变限制尚未确认。

## 接口与配置

- `BSC_RPC_URL`：区块、最终确认高度和代币检查。
- `BSC_LOGS_RPC_URL`：可选的转账日志接口；未设置时使用主接口。
- `BSC_RECEIPT_RPC_URL`：可选的交易回执接口；未设置时使用主接口。

三个接口均限定 HTTPS，拒绝重定向、错误链 ID、错误 USDT 精度和无效 JSON-RPC 响应。应用发送 `PiStarPaymentMonitor/1.0` 标识。所有独立接口先校验 BSC 链 ID 56 和官方 USDT 合约精度 18，到账仍核对确认数、最终区块、收款地址、金额及成功交易回执。

本次候选组合为 BNB 官方 `https://bsc-dataseed.bnbchain.org` 查询区块和回执，48 Club 的 `https://rpc.48.club` 查询日志。正式服务器只读验证了原游标区块哈希、连续 500 个积压区块，以及库内已有到账日志与独立官方回执的完整一致性。未注册或购买服务。公共接口可调整访问规则，后续替换时也必须验证历史 `eth_getLogs` 和已知交易，不能只检查 `eth_chainId`。

服务环境通过独立的 `zhixiang-shop.service.d/40-bsc-rpc.conf` 设置；原配置文件、收款地址、汇率、确认数、支付渠道及采购开关保持现状。私有 RPC 令牌只能保存在受限服务器配置或本机忽略目录，不能写入仓库或日志。

## 补扫与验证

RPC 日志请求按最多 50 个区块连续分页，全部页面成功且每条日志位于请求范围内才返回；中途 403、空响应、错误页或越界记录均使整批失败。BSC 每轮最多处理 500 个区块，45 秒总超时及 10 秒轮询间隔保留。成功后原子保存到账事件和游标；失败保留旧游标，不跳到当前区块，也不手工写入到账状态。

回归覆盖分段连续性、部分失败、越界/空响应、重定向、区间溢出、独立节点链验证、积压重试、确认边界和重复到账防护。生产核验需同时确认游标持续前进、追上已确认区块、最近扫描区块哈希吻合，以及新进程日志没有持续 RPC 错误。

不通过创建正式验收订单、转账或有效采购验证。真实客户确认付款后的既有自动采购仍按此前授权运行。
