# USDT 付款数量规则

BEP20 USDT 和 Plasma USDT0 的商品订单、钱包充值使用同一金额规则。

1. 基准数量 = 人民币应付金额 ÷ 支付单创建时的人民币/USDT 汇率，向上取到两位小数。第三位及之后只要还有余数，第二位加一；正好两位时不额外加一。例如 `15.041 → 15.05`、`15.040 → 15.04`、`15.999 → 16.00`。使用十进制商和余数运算，不经过浮点数。
2. 同一网络、代币、收款地址下，先尝试基准数量；已经分配过时，依次尝试 `+0.01`、`+0.02` 等，选最小可用数量。递增最多 `0.99 USDT`，共 100 个候选，其他基准金额也可能占用其中的金额。这是订单识别调整，页面展示及复制的是最终应付数量。
3. 数据库原子保留精确金额，支持并发创建和请求重试。过期、成功或已取消订单的历史金额仍然占用，防止迟到付款落到新客户的订单。100 个候选都被占用时返回 `chain_unique_amount_capacity_exhausted`，不继续涨价，不覆盖旧单；客户可使用其他支付渠道，运营应规划独立收款地址方案。仅等旧单过期不会释放容量。
4. 新支付单固定返回两位小数（如 `15.04`、`20.00`）。旧六位支付单保留原金额、汇率、地址和有效期，继续按原规则识别，不修改历史应付数量。
5. 链上仍按代币原始精度保存整数数量：BEP20 为 18 位、Plasma 为 6 位。匹配使用精确原始数量，不能把实际到账数量再取整或只比较前两位。少付、多付、分笔、迟到和重复转账仍进入人工核查；每笔支付最多确认一次。

商品售价、人民币订单金额和钱包入账金额不因识别调整改变。客户按收银页完整数量到账；交易所扣除的提现手续费需自行补足。新规则只影响创建新支付单，刷新旧单不会重新报价。

此规则保留自动识别与迟到款保护，但共享固定地址的两位金额容量有限。不要为释放容量删除历史发票、舍入旧金额或重新分配过期金额。

验证使用模拟链与临时数据库，覆盖向上取整边界、同额及相邻报价并发、容量上限、旧六位支付单和两条网络的精确到账。实际本机入口另外核验商品订单和钱包收银页；不主动执行真实转账或采购扣款。
