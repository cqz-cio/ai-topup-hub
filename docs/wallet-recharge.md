# 钱包充值与后台余额调整

## 操作入口

- 商城 **个人中心 → 我的钱包**：输入人民币充值金额，选择已启用的支付渠道。BEP20、Plasma 充值详情显示对应链、币种、收款地址、精确六位小数金额和付款期限。按该笔充值单展示的信息付款，链上确认后自动计入该用户的人民币余额。
- 后台 **支付渠道**：配置提供方、启用状态、金额范围、付款角色及付款类型。钱包充值要求付款类型包含 `wallet`（不限制类型也允许），商品支付使用 `order`。
- 后台 **钱包管理 → 钱包配置**：进一步指定允许充值的渠道，不选择表示不加额外限制。渠道仍须启用并满足用途、用户和金额条件。
- 后台 **用户管理 → 用户列表 → 用户详情 → 钱包明细**：选择增加或扣减余额，填写金额和必填备注，点击确认调整。余额、流水、操作管理员与备注一并保存，扣减不能超过余额。

首次使用受保护的财务功能时，超级管理员需要本人阅读并完成现有合规声明。钱包明细现已接入同一确认弹窗；确认后自动加载余额和流水，再由管理员主动提交调整。普通管理员不能代为确认，相关 API 仍保留鉴权和权限校验。程序修复与发布不会自动代签声明，也不会自动给任何真实用户增加余额。

## 修复范围

此前两条链上渠道默认仅支持商品订单，网关也要求商品订单 ID，因此钱包充值不可用。现为钱包充值保存独立的支付期限，并从已持久化且待付款的充值单/支付单校验期限、金额与币种。链上确认沿用已有充值入账事务和幂等流水机制。

新建链上渠道默认支持 `order` 与 `wallet`；已有渠道的付款类型需显式维护，启动不会覆盖商户的渠道配置。服务端渠道列表现在也遵循钱包配置的充值渠道限制。充值详情的前端兼容平铺和嵌套响应，完整保留链、精确金额、币种和地址。

本次用临时数据库、模拟链验证 BEP20/Plasma 充值、确认前不入账、确认后只入账一次、重复通知与到期处理；并在日常本机入口验证后台加减余额、流水、两条渠道和桌面/手机收银页。真实资金支付与采购未进行验收。
