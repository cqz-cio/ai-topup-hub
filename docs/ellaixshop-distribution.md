# ELLAIXSHOP 供货接入

本站使用后端 `acg-faka` 适配器连接 ELLAIXSHOP 商户 1039。客户在本站付款，后端确认付款后使用商户余额采购并保存卡密，客户从本站订单详情取卡。商户密钥只在后端签名和加密存储，不发给购买者。

现有 12 款映射见 [映射表](catalog/qzweb-ellaixshop-mappings.json)。`qzweb-52/53/62/1` 未由该商户提供，保持未绑定，不按近似名称替换渠道。本站售价不随商户报价或库存刷新改变，`auto_sync_price=false`，`qzweb-55` 为 1160.00 元。自动充值关闭。商户余额与库存会变化，不能沿用历史截图或报告数值。

客户付款后的自动采购已获授权，尚未完成真实资金验收。模拟测试和只读探测不代表真实收款、扣款及交付通过；不要主动提交有效采购或将测试订单改为已付款。

## 接入设置

后台连接使用协议 **Acg-Faka / ELLAIXSHOP**、站点 `https://ellaixshop.com`、商户 ID `1039`、CNY 汇率 `1`，密钥由管理员私下配置。修改连接未填写新密钥时保留原密钥。当前目录使用逐商品售价，保持自动同步价格关闭，不用统一加价覆盖售价。

白名单需要登记本站后端实际出网 IP。只支持自动发卡、单规格、无额外表单的商品；多规格、手工交付或要求买家填写账号/session 的商品不应直接套用已有映射。

已有连接和映射不要重复创建。`scripts/connect-ellaixshop.ps1` 可创建或复用连接、测试只读查询、导入指定未上架商品；它不采购或自动上架。所需 `ZXA_ADMIN_TOKEN` 和 `ELLAIXSHOP_MERCHANT_SECRET` 仅在调用进程私下设置，不写进命令文件或仓库。

## 交易与异常处理

1. 本站后端确认付款，采购 worker 读取对应商品/SKU 映射。
2. 数据库原子登记采购状态，阻止并发或重复队列任务重复采购。
3. 重新校验库存、报价、数量及商户余额；报价不能超过付款订单保存的成本上限。
4. 采购成功后保存上游订单号及卡密；订单号按字符串保存，保留前导零。
5. 即时返回卡密则交付；延迟交付按原上游订单号查询，不重新采购。

正式环境使用 `-mode storefront` 和持久化 Redis，包含付款监听、采购与交付 worker、每分钟恢复任务。单独 `-mode api` 不会完成完整自动交付；不需要填写上游回调地址。

余额/库存不足或超出成本上限时保留已付款待处理订单，不伪造交付。扣款请求超时、响应缺失订单号或结果不明时进入 `manual_review`，必须到上游核对原交易；不能自动重发。超时的 `submitting` 也进入核对流程。已经保存的卡密可恢复交付，无需重复采购。Shared API 不提供余额采购撤销/退款接口，退款需结合实际交易人工处理。

## 库存维护

生产 `zhixiang-stock-sync.timer` 每 300 秒调度 [库存脚本](../scripts/sync-ellaixshop-stock.py)，凭据保存在服务器私有目录，通过回环地址访问后台。不要重复启动监听式同步助手。本地离线预览使用单独的禁用连接及库存缓存，不使用生产凭据采购，也不向生产写数据。

## 协议依据

签名与请求格式依据 [官方 Shared 商品接口](https://github.com/lizhipay/acg-faka/blob/ea4f4e6d181d59165168c543c53b1d3801bf0db9/app/Controller/Shared/Commodity.php) 和 [签名实现](https://github.com/lizhipay/acg-faka/blob/ea4f4e6d181d59165168c543c53b1d3801bf0db9/app/Util/Str.php)。密钥仅用于本地签名，请求携带 `app_id`、`sign` 及业务参数，不发送明文 `app_key`。项目保留模拟供应商测试，覆盖成本校验、并发提交、未知结果、延迟发卡及恢复。
