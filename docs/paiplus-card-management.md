# PAIPLUS 交付卡密管理

商城后台「商品管理 → 卡密库存 → PAIPLUS 交付卡密」管理已交付的兑换卡。原「库存卡密」继续管理可销售库存，已交付 PAIPLUS 不会重复进入可售库存。兑换站的加密 SQLite 是双码和使用状态的唯一来源，商城后端代理管理请求，不复制明文卡密到商城库存表。

## 发货与状态

- 原有自动采购完成后，一对一绑定时同时保存订单 ID/编号、商品 ID/SKU/名称；列表按订单、商品名称、完整本站卡密或完整上游卡密搜索。旧记录仍可查看，旧 reference 可恢复订单 ID。
- 列表遮罩两张卡密。具有查看权限的管理员在详情中显式读取双码；关闭、切换订单、离开页面或退出登录清除明文。请求禁止缓存，搜索使用 POST，日志不写卡密或会话凭据。
- 状态包括未使用、已使用、充值处理中、销毁核验中、已销毁、已失效。未使用指未兑换，并非未发货。充值结果持久保存；定时只读核验上游用于发现站外使用。退款以当次销毁结果为准，不依据缓存的未使用状态。

## 退款前销毁

管理员填写原因并确认后，先事务锁定卡密为 revoking，再查询上游 lookup。只有同时返回匹配的原卡密、status=unused、used=false、can_resubmit=true 才成功。仅 used=false 不足以判断可退。

已使用或失效提示「卡密无效，销毁失败」。充值已提交、正在核验、状态未知、网络故障等不能确认安全的情况拒绝销毁。销毁检查与客户提交互斥，服务重启保留锁定状态并恢复同一个操作，重复请求不会重复发卡或充值。

成功后本站卡密永久失去兑换能力，所有单张、批量、恢复和确认提交入口均拦截；不能重新启用或将同一上游卡重新发给其他客户。仍保留加密双码关系、操作人、原因、时间及结果，供核账和上游退款使用。不会自动退款、调用上游销毁或保证已泄露的原始上游卡不能在别处使用。

## 配置与权限

兑换站新增独立 REDEMPTION_MANAGEMENT_TOKEN，商城后端设置相同 PAIPLUS_MANAGEMENT_TOKEN，沿用 PAIPLUS_ORIGIN。令牌至少 32 字符，必须不同于原发货和独立后台口令，保存在服务器私有 env 文件；不写入前端、仓库或公开发布清单。

商城沿用原管理员 JWT 和 RBAC。新增 POST 权限：/admin/card-secrets/paiplus/query、reveal、check、revoke。超级管理员和运营角色可用；客服、财务、只读和对接角色不会因旧库存权限自动获得双码/销毁权限。客户端不能伪造操作人。

## 验证与发布

测试覆盖发货 → 后台列表 → 双码查看 → 未使用销毁 → 兑换拦截，以及另一张卡正常充值后拒绝销毁；并验证请求幂等、并发提交、上游超时、未知状态、响应串码、重启恢复及权限隔离。全部充值/销毁测试使用隔离模拟数据，不代表真实付款或真实上游充值验收。

发布前一致性备份两站数据库、私有配置及程序。Node 自动增加 cards 元数据字段、card_operations 和 audit.actor；商城只增加管理权限规则。不重置订单门槛、采购时间边界、价格、订单或历史交付，不上传本机数据库。

回退不得回灌业务库。存在 revoking/revoked 卡密后不能切回不识别这些状态的旧兑换程序；保留当前兼容的兑换服务和加密主密钥，必要时只回退商城页面/后端。永久销毁状态及待完成操作必须持续生效。
