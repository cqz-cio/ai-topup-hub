# 功能状态与任务处理

当前 storefront 运行方式支持支付、采购和发货，并处理分销结算、推广佣金到期确认及对账任务。库存同步继续由服务器独立定时器每 300 秒执行，不启动完整 worker。

| 功能 | 当前处理方式 |
| --- | --- |
| 分销结算 | 每分钟确认已到期流水，更新可用余额；未到期及已撤销流水不提前结算，重复执行不重复入账。 |
| 推广返利 | 保持原有关闭设置。用户中心读取实时启用状态与账户状态；关闭时不能开通或申请提现，历史记录可查看。佣金确认任务就绪不等于开启返利。 |
| 对账 | 提交后由 storefront 消费。队列不可用时返回失败；兼容数字与字符串上游订单号。查询失败、缺少编号或金额无法核实时标记未完整核验，不计为匹配成功。此类任务不自动重复重试，排查后重新发起对账。 |
| 系统二级域名 | 当前未配置根域名，分配输入及按钮禁用并显示原因；不替用户选择域名、修改解析或签发证书。 |
| 库存同步设置 | 显示由独立定时任务管理，隐藏不生效的周期、分页及并发设置；下单前库存校验仍可设置。 |
| 站内兑换 | 自动充值保持关闭，`/redeem` 显示未开放和订单兑换指引；不加载兑换表单或启动轮询。 |
| Telegram 群发 | 当前不提供新建或发送操作，直接请求也会被拦截；已有记录可查看。 |
| 定时告警巡检 | 库存、待支付及支付失败的定时检查暂未开放，相关频率设置隐藏并说明原因。订单支付成功、人工交付等事件通知保留原配置。 |

后台 `/api/v1/admin/system/features` 仅向已登录管理员返回可用性布尔值及原因，不包含私有配置，也不修改业务权限。公开配置仅增加 `features.redemption`。功能状态读取失败或字段缺失时，相关提交保持不可用，可重新加载。

供货渠道 `acg-faka` 的订单查询提供交付状态，但当前不返回可独立核验的金额。可选择“状态对账”；“金额对账”或“全量对账”会明确提示金额不可核对，金额需与供货商账单核实，不使用本站保存的采购金额冒充上游查询结果。

验证不进行真实付款、采购或提现。现有本机库没有用户及分销商，且财务声明未确认：这些场景使用临时数据库回归；日常入口检查实际后端、调度、功能状态、管理页面及原有声明拦截，不代签声明或新增管理员。生产验收使用现有登录和只读检查。
