# 上游成交金额对账

后台「对接管理 → 对账中心」的金额对账、全量对账支持 ELLAIXSHOP / `acg-faka` 的原订单成交金额。历史未完整核验的任务保留原结果，需要重新发起对账。

## 金额来源

1. 使用已有商户签名查询 `/shared/commodity/query`，确认原订单属于当前商户并读取交付状态。
2. 仅金额、全量对账调用同一 HTTPS 站点的 `/user/api/order/state`。该接口接收 `tradeNo`，返回 `trade_no`、`amount`、`status`；不发送商户 ID、签名或密钥。
3. 原样比对字符串订单号，保留前导零；两处支付状态都须为已付款。金额按十进制精确比较，CNY 最多两位小数，不用浮点计算或四舍五入掩盖差异。显式返回其他币种时拒绝核验，采购记录币种也须一致。

协议依据为 [官方签名查询](https://github.com/lizhipay/acg-faka/blob/ea4f4e6d181d59165168c543c53b1d3801bf0db9/app/Controller/Shared/Commodity.php) 与 [官方订单状态接口](https://github.com/lizhipay/acg-faka/blob/ea4f4e6d181d59165168c543c53b1d3801bf0db9/app/Controller/User/Api/Order.php)。2026-10-14 已对本站 3 笔既有已交付采购订单进行上游只读核验，订单归属、编号、付款状态、107.50 CNY 成交金额均一致；没有创建订单或采购。

金额来源是上游该笔订单保存的成交总额；不用当前商品价格、采购前后余额差或本站采购金额代替。该接口不是退款流水或退款净额接口，线下退款、人工余额调整仍需核对上游账单。用户账单接口 `/user/api/bill/data` 需要上游用户会话，不拿 Shared 商户密钥冒充用户登录，不额外保存上游登录密码。

## 失败与频率

- 订单不属于商户、金额缺失/非法、订单号不符、未付款、币种不符、429/网络错误均不计入匹配成功；任务显示未完整核验，处理原因后重新发起。
- 状态对账及发卡轮询保留原签名查询，不依赖金额接口。
- 上游金额接口公开实现限制同 IP 每 600 秒 120 次；当前单实例共用限速，最多突发 5 次，后续每 6 秒一次。不要另起多实例对账 worker。大批量任务应按时间分段，受现有队列超时限制。
- 对账只新增任务及差异审计记录，不修改采购成本、售价、订单状态、余额或发卡内容，不自动补扣款或重新采购。

## 验证

模拟供应商覆盖金额一致、精确一分钱差异、零金额、缺失/非法金额、错误订单号、前导零、未付款、币种错误、限流/超时和原交付查询独立性；结果保存及重复执行保护沿用对账服务。测试与正式只读核验不代表真实收款、扣款或采购验收。
