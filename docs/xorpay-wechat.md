## 手续费与运营配置

用户已确认由客户承担 1.6% 手续费，不足一分钱向上取整。规则快照见 [xorpay-payment-fee-policy.json](xorpay-payment-fee-policy.json)。

手续费为 `ceil(本金 × 0.016 × 100) / 100`。本金先应用现有优惠与钱包抵扣规则；钱包充值只将充值本金计入钱包，手续费不会变成可消费余额。前端显示费用与实付预估，后端计算最终金额并保存支付快照。XorPay 下单和回调金额核验都使用含手续费的实付金额。

后台「支付管理 → 支付渠道 → 微信支付 → 编辑」维护应用 ID、App Secret、通知地址、费率和启用状态。配置为 XorPay / 微信 / 二维码，付款类型选择订单购买、钱包充值，费率 `1.60`，固定费 `0.00`，最小金额 `0.01`，最大金额 `0.00`（不设上限）。

该渠道单独勾选「向客户收取渠道手续费（不足一分向上取整）」。这是本渠道的覆盖配置；全局「手续费承担策略」保持原值，不必为启用微信而打开全局加收。TRON（TRC20）、BEP20、Plasma 的配置及费率保持各自原值，微信手续费不套用到 U 渠道。

通知地址为 `https://www.qzweb.cloud/api/v1/payments/callback`，通过上海现有 API 通道到新加坡后端。商户密钥只在服务端保存，后台返回掩码，公开渠道接口和前端构建不含密钥。本机私有配置位于忽略的 `work/codex-runtime/xorpay/private/xorpay.credentials.json`，不能提交或打印。

## 支付与交付行为

- 按文档签名后向 XorPay 提交 Native 下单，二维码有效期不超过商城支付期限。已兼容接口将有效期返回为字符串或数值，以及合法的 HTTP、HTTPS、微信二维码地址。
- 仅在异步回调签名有效、订单及 XorPay 单号匹配、币种与实付金额一致后确认付款。事务成功后返回 HTTP 200，失败返回非 200 供平台重试。重复通知复用既有支付幂等处理，不重复给钱包入账或发起采购。
- 查询接口的未签名结果不用于把订单改为已付款。订单付款沿用既有支付后采购发卡流程，钱包付款沿用充值入账流程。
- 当前为扫码能力，未接入 JSAPI 或自动跳转的手机收银台。普通 Native 二维码一般不支持同一手机相册/长按识别，具体以 XorPay 渠道能力为准。
- XorPay 服务费余额需要单独维护。`fee_error` 表示平台余额不足；客户手续费不会自动充值该账户。
