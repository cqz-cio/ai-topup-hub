# 交付内容按需读取

订单列表和普通详情仅返回交付状态、类型、时间等元数据。卡密正文、结构化交付信息和商品私有使用说明在客户点击“查看交付内容”后单独读取。父订单与子订单遵循相同规则。

## 接口与权限

- 登录客户：`GET /api/v1/orders/:order_no/fulfillment`，使用现有用户鉴权，服务端重新校验用户 ID、订单归属及店铺租户。
- 游客：`GET /api/v1/guest/orders/:order_no/fulfillment`，每次通过现有 `Authorization: Guest ...` 请求头验证邮箱与订单查询密码，凭据不放入 URL。
- 后台：`GET /api/v1/admin/orders/:id/fulfillment`，独立于订单列表和详情权限。预置客服角色拥有查看与下载交付权限；财务与只读审计角色不会因能看订单而获得卡密。超级管理员沿用现有权限。
- 交付内容必须已有付款记录且交付状态为 `delivered`。原有下载接口保留，并执行同样的付款、交付状态和归属检查。
- 查看、下载接口设置 `Cache-Control: private, no-store, max-age=0`、`Pragma: no-cache` 和 `Vary: Authorization`。后台查看与下载记录操作管理员 ID、订单 ID 和动作，日志不记录交付内容。
- 后台采购列表及普通采购详情也不预载上游交付正文。采购详情的“查看交付内容”通过现有、单独授权的上游交付下载接口读取。

普通详情、创建订单、取消订单、后台状态更新返回的订单均不夹带交付正文。原有渠道 API、履约流程和交付邮件保持各自的授权与交付契约。

## 页面行为

经典与 Vault 客户模板共用受保护交付组件。默认显示锁定提示；点击后显示加载状态，成功才展示卡密、复制/下载操作与经过原有净化处理的说明；失败保留锁定状态并允许重试。后台订单与采购详情采用相同的按需交互。

点击隐藏、切换订单、切换登录凭据或卸载页面会清除组件中的交付数据，同时使未完成请求的结果失效，避免旧响应回填到另一订单。交付正文不写入 Local Storage 或 Session Storage。复制或下载是用户主动保存到设备的操作，不会随隐藏而撤回。

下载请求完成时也重新检查页面和登录上下文，切换订单、退出或关闭页面后的迟到响应不会继续保存。历史已交付订单不需要迁移或重新发卡；刷新后的页面使用同一套权限和按需读取规则，卡密原值、交付时间和有效期不变。此前已复制、下载或通过邮件交付的内容无法撤回。

客户查看时，授权后的卡密仍会进入其浏览器响应，这是网页展示所必需的。此调整减少普通查询与列表批量读取带来的暴露面，并不加密数据库，也不能抵御已经控制合法客户会话、交付权限管理员或服务器的攻击者。

## 验证与发布

使用不可兑换的模拟卡密和内存数据库测试；不创建正式验收订单，不触发付款或供应商采购。覆盖普通响应及嵌套子订单脱敏、游客凭据、用户/租户归属、独立后台权限、未付款/未交付拒绝读取、禁止缓存、隐藏后的迟到响应与错误重试。前后台类型、测试和生产构建均须通过，实际浏览器检查包含两模板、桌面和窄屏。

本改动涉及后端与两套前端，需要成套发布并保留已有 Nginx 撤下资源规则。发布前仍须按项目流程在日常本地入口验证、备份生产数据；不能仅发布前端而宣称接口已脱敏。本次正式发布结果见下方记录。
