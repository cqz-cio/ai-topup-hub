# 版本与发布规则

## 唯一主线

`main` 维护绿色 Go + Vue 商城。后续功能从 `main` 建立短期 `codex/*` 分支，验证后合回 `main`；完全合并的分支可删除，Git 保留历史。

`baseline/green-20261012` 固定整理前的绿色源码 `419141e`，包含旧 React 展示页，可追溯恢复。它是源码基线，不等同于服务器二进制的精确 Git SHA。

2026-10-12 早前的仓库整理没有替换线上程序。后续已发布品牌修正及 Plasma 支付，当前生产基准与构建来源见 [生产说明](../ops/tencent/README.md) 和 [基准清单](../ops/tencent/production-baseline.json)。

## 三类版本分别记录

| 对象 | 标识 | 保存方式 |
| --- | --- | --- |
| 源码 | 完整 Git SHA、源码标签 | GitHub |
| 发布程序 | 发布号、构建来源、程序和资源 SHA256 | 发布清单、服务器 releases |
| 业务数据 | 数据库备份时间、校验结果 | 私有备份，不进入 Git |

以后构建时记录 Git SHA、是否存在未提交修改、构建命令及工具版本；部署后记录实际二进制 SHA256 与发布目录。来源核实后才把某个 Git 提交标为线上生产版本。

## 发布流程

1. 核对 `main` 的 HEAD、工作区状态、本地实际运行版本和现有生产发布号；确认本次改动范围。
2. 先在日常本地入口完成相关测试及实际页面核验，包括配置、支付渠道、商品说明和数据变更。后端有改动时通过本地生命周期脚本重建并重启，不能用临时测试入口代替 `5173`、`5174` 和 `8080` 的核验。
3. 保存本地验证结果，通过后推送已验证提交并核对远端 SHA。未通过的改动先修复，不上线。
4. 部署前对线上数据库做一致性备份，同时备份配置、凭据和现有发布。
5. 应用程序变更从已验证的干净提交构建前台、后台及 Go fullstack 程序，保存不可变清单；上传程序和资源，保留 `/srv/zhixiang/shared` 数据与配置，切换发布目录。仅商品说明或维护脚本变更按实际范围部署，保留程序的真实构建来源；仅文档变更不替换程序。
6. 上线后对照本地验证结果，核对页面、健康、支付渠道、商品说明、售价、Redis、库存定时器和 storefront 任务。订单、凭据及实时库存分别维护，不用本地数据覆盖生产；不主动进行真实付款或采购测试。
7. 保存核验结果与旧发布，再标记对应发布标签。

GitHub CI 在 `main`、`dev` 推送及 PR 上验证；`v*` 标签触发 GoReleaser 发布包。没有自动部署新加坡的 GitHub 工作流，推送主分支或源码基线标签不会替换生产程序。

嵌套或管理工作区构建时显式设置 `GIT_DIR` 为 `git rev-parse --absolute-git-dir` 的结果、`GIT_WORK_TREE` 为当前源码根目录，避免 Go 自动读取外层工作区的 Git 信息。发布前用 `go version -m` 核对 `vcs.revision` 与已验证提交一致，且 `vcs.modified=false`。

不要用上游通用安装器覆盖智享A社环境，不要将本机库上传覆盖生产库。恢复程序版本和恢复业务数据是不同操作。
