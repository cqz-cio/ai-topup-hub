# 分销申请与功能状态

分销申请受运行配置中的 `reseller.enabled` 和 `reseller.self_apply_enabled` 共同控制，二者均开启才允许提交。后台 **分销商管理 → 分销概览** 展示实际「分销功能」和「用户申请」状态；后台管理页面在申请关闭时仍可查看已有记录。

用户端以接口返回的 `can_apply` 决定是否显示申请表。未申请、已驳回且平台开放申请时可提交；提交后进入待审核，不自动开通。已开通、审核中、停用、申请关闭及加载失败分别显示状态，加载失败时可重试。

后台 **分销商审核** 可审核申请。审核通过后，分销商继续配置自己的域名与店铺。申请开通不自动分配二级域名，不代表自定义域名已经完成 DNS、HTTPS 或接入验证。

## 环境配置

- 本地使用日常 `8080/5173/5174` 入口，主站 Host 包含 `localhost`、`127.0.0.1`、`::1`，采购保持关闭。
- 正式开启前必须在 `reseller.main_hosts` 保留 `www.qzweb.cloud`、`qzweb.cloud`、现有服务器 IP 入口与回环地址，避免主站被误认为未知分站。
- 使用现有代理传递的原始 Host，保持 `trusted_forwarded_host=false`。不要信任客户端自报的 `X-Forwarded-Host`。
- `subdomain_base` 在准备好对应泛域名 DNS、TLS 前保持为空。分销申请可以单独开放。
- 配置文件为运行时来源，修改后需重启后端。环境私有配置分别维护，禁止用本地库覆盖生产。

## 验证要求

先在本地验证开关一致性、申请进入审核、重复提交、驳回重申请、审核开通、停用及主站域名识别；临时账号与申请在验证后清理。随后从验证通过的源码构建、推送及发布，备份线上数据与配置，核对公开商城、后台状态、原订单、价格、支付及库存同步。正式站验收只读，不代真实客户提交申请或自动审批。
